## 认证模块的权限校验机制

### 1. 多层认证架构

Gotify采用三层认证架构：
- **用户认证（Basic Auth）**：用户名密码认证
- **客户端认证（Client Token）**：会话级别的客户端token
- **应用认证（Application Token）**：应用级别的token

### 2. 认证中间件工作流程

文件位置：`auth/authentication.go:45-120`

```go
// 认证状态枚举
const (
    authStateSkip authState = iota  // 跳过当前认证方式
    authStateForbidden              // 禁止访问
    authStateNotElevated            // 会话未提升
    authStateOk                     // 认证成功
)
```

**2.1 核心认证评估流程**

```go
func (a *Auth) evaluate(ctx *gin.Context, funcs ...func(ctx *gin.Context) (authState, error)) bool {
    for _, fn := range funcs {
        state, err := fn(ctx)
        if err != nil {
            ctx.AbortWithError(500, err)
            return true
        }
        switch state {
        case authStateForbidden:
            a.abort403(ctx)
            return true
        case authStateNotElevated:
            ctx.AbortWithError(403, errors.New("session not elevated..."))
            return true
        case authStateOk:
            ctx.Next()
            return true
        case authStateSkip:
            continue
        }
    }
    return false
}
```

**2.2 客户端认证处理**

文件位置：`auth/authentication.go:143-176`

```go
func (a *Auth) handleClient(checks ...func(*model.Client) (authState, error)) func(ctx *gin.Context) (authState, error) {
    return func(ctx *gin.Context) (authState, error) {
        token, isCookie := a.readTokenFromRequest(ctx)
        if token == "" {
            return authStateSkip, nil
        }
        client, err := a.DB.GetClientByToken(token)
        if client == nil {
            return authStateSkip, nil
        }
        RegisterClient(ctx, client)
        
        // 执行额外检查（如是否为管理员、是否提升权限）
        for _, check := range checks {
            if state, err := check(client); err != nil || state != authStateOk {
                return state, err
            }
        }
        return authStateOk, nil
    }
}
```

### 4. Token读取优先级

文件位置：`auth/authentication.go:205-247`

```go
func (a *Auth) readTokenFromRequest(ctx *gin.Context) (string, bool) {
    // 优先级顺序:
    // 1. Query参数 (?token=xxx)
    // 2. X-Gotify-Key 头部
    // 3. Authorization Bearer 头部
    // 4. Cookie (gotify-client-token)
    if token := a.tokenFromQuery(ctx); token != "" {
        return token, false
    } else if token := a.tokenFromXGotifyHeader(ctx); token != "" {
        return token, false
    } else if token := a.tokenFromAuthorizationHeader(ctx); token != "" {
        return token, false
    } else if token := a.tokenFromCookie(ctx); token != "" {
        return token, true
    }
    return "", false
}
```

### 5. 前端认证拦截器

文件位置：`ui/src/apiAuth.ts:5-23`

```tsx
export const initAxios = (currentUser: CurrentUser, snack: SnackReporter) => {
    axios.interceptors.response.use(undefined, (error) => {
        if (!error.response) {
            snack('Gotify server is not reachable, try refreshing the page.');
            return Promise.reject(error);
        }

        const status = error.response.status;

        // 401未授权时尝试重新认证
        if (status === 401) {
            currentUser.tryAuthenticate().then(() => snack('Could not complete request.'));
        }

        // 处理错误响应
        if (status === 400 || status === 403 || status === 500) {
            snack(error.response.data.error + ': ' + error.response.data.errorDescription);
        }

        return Promise.reject(error);
    });
};
```

const ConfigurerPanel = ({initialConfig, save}: IConfigurerPanelProps) => {
    const [unsavedChanges, setUnsavedChanges] = React.useState<string | null>(null);
    const onChange = React.useCallback(
        (value: string | null) => {
            let newConf: string | null = value;
            if (value === initialConfig) {
                newConf = null;
            }
            setUnsavedChanges(newConf);
        },
        [initialConfig]
    );
    return (
        <div>
            <CodeMirror value={initialConfig} theme={material} onChange={onChange} />
            <br />
            <Button
                variant="contained"
                color="primary"
                fullWidth={true}
                disabled={unsavedChanges === null || unsavedChanges === initialConfig}
                className="config-save"
                onClick={() => {
                    const newConfig = unsavedChanges;
                    save(newConfig!).then(() => {
                        setUnsavedChanges(null);
                    });
                }}>

## 架构总结

### 1. 关键设计模式

**1.1 状态提升模式**
- 弹窗的显示/关闭状态由父组件管理
- 通过回调函数（fOnSubmit, fClose）实现子父组件通信

**1.2 MobX 状态管理**
- 使用 @action 装饰器标记状态修改
- 使用 observable 跟踪数据变化
- 使用 createTransformer 优化渲染性能

**1.3 中间件认证链**
- 多层认证策略（用户、客户端、应用）
- 灵活的权限检查组合机制
- 支持会话提升（Elevation）

### 2. 数据流关键控制点

| 层级 | 控制点 | 职责 |
|-----|--------|------|
| UI层 | 弹窗组件 | 表单展示、输入校验、用户交互 |
| Store层 | AppStore/MessagesStore | 状态管理、API调用、数据转换 |
| API层 | Gin Handlers | 请求绑定、业务逻辑、响应格式化 |
| 认证层 | Auth Middleware | Token读取、身份验证、权限检查 |
| 数据层 | Database | 数据持久化、查询优化 |

### 3. 安全特性总结

1. **多级别认证**：支持用户、客户端、应用三种token类型
2. **权限提升机制**：敏感操作需要额外的会话提升
3. **用户资源隔离**：仅允许操作属于当前用户的资源
4. **Token多渠道支持**：Header、Query、Cookie多种传递方式
5. **自动重连机制**：前端自动处理认证失效场景

### 4. 性能优化点

1. **虚拟滚动**：使用 Virtuoso 实现消息列表高性能渲染
2. **MobX 转换缓存**：createTransformer 缓存计算结果
3. **增量加载**：消息分页加载（since 参数）
4. **乐观更新**：UI 即时响应，后台同步数据
